# 方法

这个工具回答一个问题：**给定一组标注了标称 RPM 的稳态循环，RPM 与声学音高之间的真实关系是什么，而每个单独的循环需要做什么才能落在这条关系上？**

它分四个阶段求解。

## 阶段 1 —— 音高不变的表示

同一台引擎在不同 RPM 下的两段录音，在音高*和*频谱形状上都不同。要比较它们，必须让音高变成一种平移。

1. **裁剪。** 每个循环的首尾各 5% 被丢弃（比例可配置，默认 `0.05`），以去除淡入淡出与循环边界伪影。
2. **加窗幅度谱。** 用 Hann 窗（`scipy.signal.windows.hann`）取帧，并用 `rfft` 变换。每个资源提取多个窗口，稍后再归约。
3. **对数压缩。** 幅度用 `log1p` 压缩，避免少数极响的谐波主导比较。
4. **音分网格重采样。** 频谱被插值到对数网格上：

   ```text
   cents(f)  = 1200 · log2(f / f_min)
   f(cents)  = f_min · 2^(cents / 1200)
   ```

   在这个网格上，把声音移调 *n* 个音分，正好等于平移 *n* 个频点。

5. **频谱白化**（默认开启）。从对数频谱中减去高斯平滑包络，只留下局部谐波结构。没有这一步，相关性主要度量的是*每个谐波有多响*，而不是*它在哪*；有了它，相关峰反映的是音程关系。
6. **多窗中位数。** 各窗口的剖面用跨窗口的**逐频点中位数**合并，因此单个噪声窗口无法决定这个资源的测量结果。

## 阶段 2 —— 两两音程测量

对每一对循环，通过相关它们的音分网格剖面求出相对音高音程。

由于两个循环的标称 RPM 不同，期望音程可以被近似地预知：

```text
expected_interval_cents(a, b) = 1200 · log2(rpm_b / rpm_a)
```

随后的搜索分两个阶段：

| 阶段 | 搜索范围 | 用途 |
|---|---|---|
| **粗搜** | 完整 ±1200 音分（可配置 `coarse_search_margin_cents`） | 为 **RPM 相邻**的对找到真实音程 |
| **精搜** | 在预测值附近 ±150 音分（`refine_search_radius_cents`） | 为**非相邻**的对做精确测量 |

每次测量都带有质量证据：峰值相关性、峰突出度、窗口间一致性，以及峰值是否落在搜索边界上（命中边界意味着「搜索范围太窄」，这被当作警告而不是结果）。

## 阶段 3 —— 带锚点的稳健全局求解

两两音程是*相对*的：测量 `A → B → C` 会累积误差，而一段坏录音就能拖累整条链。因此改为同时求解所有资源。

每次测量给出一个差分方程：

```text
A_j − A_i ≈ D_ij
```

它成为线性系统的一行，并按测量质量加权。该系统存在规范自由度（给每个 `A` 加上同一个常数不会改变任何东西），因此求解时使用**等式约束**把某个锚点固定在 0 音分，而不是任意钉住第一个文件。

求解采用**配合 Tukey biweight 的迭代重加权最小二乘**：

```text
scale  = max(2.5, 1.4826 · median(|residuals|))     # MAD-based
cutoff = 4.685 · scale
w      = (1 − (r/cutoff)²)²                          # floored at 1e-4
```

最多 12 次迭代，当权重不再变化时收敛。测量错误或有噪声的录音会被逐步降权，而不是把全局解拽离目标。

**锚点选择**是刻意的：在初步置信度超过低置信度阈值的资源中，锚点取**最接近中位 RPM**的那一个，并以较高置信度裁决平局。一个居中且测量良好的循环，远比任意选择的一个更适合作为基准。

随后每个资源都会得到一个置信度和一项诊断：

```text
pair_quality = 0.65 · correlation_component
             + 0.25 · peak_prominence
             + 0.10 · window_consistency
fit          = exp(−|solver_residual| / 12)
confidence   = 0.75 · quality(evidence, fit) + 0.25 · graph_coverage
```

诊断包括：`LOW_CONFIDENCE`、`LOW_CONNECTIVITY`（某个资源的配对太少）、`POOR_GLOBAL_FIT`（中位残差超出容差）以及 `NON_MONOTONIC_MEASUREMENT`（求解把 RPM 较高的资源放到了 RPM 较低的资源之下，这对稳态引擎循环来说在物理上不合理）。权重塌缩的配对被标记为 `OUTLIER`。

另请注意，配对图必须是**连通的**：如果某个资源与其余资源之间没有有效的测量路径，求解会拒绝运行，而不是悄悄给出一个没有依据的数字。

## 阶段 4 —— 单调主映射

求解得到的声学音高随后对 RPM 做回归：

```text
model(R) = a · log(R + K) + b  +  residual(R)
```

- `log(R + K)` 项是物理基线：音高大致与 RPM 的对数成正比。
- 残差项是**非参数且带单调性约束的**，用解析梯度优化器拟合，平滑权重通过选择确定，而不是手工指定。
- 最终曲线通过 **PCHIP** 插值求值（`scipy.interpolate.PchipInterpolator`），它本身保单调，且外推被禁用。

结果是一条不可能回折的曲线，这正是它可以被安全地转成 RTPC 控制点的原因。

## 阶段 5 —— 导出

两张 UTF-8（带 BOM）表格与两张图表：

- **Asset offsets**：测量音高、模型音高、原始偏移、整数偏移、置信度、状态。
- **RTPC 控制点**：逐资源的 RPM → RTPC 音高，以及合成后的最终音高。
- **图表**：主映射与测量点的对照图，以及逐资源的 RTPC 曲线。

产生这些数字的精确公式见 `docs/rtpc-math.zh-CN.md`。
